## 1. Overview

The **ASVspoof 2019 Logical Access (LA)** dataset is the standard benchmark for evaluating speech countermeasure systems. It was released as part of the ASVspoof 2019 challenge organized by INRIA (France), the University of Edinburgh, Nagoya University, and the University of Eastern Finland.

The dataset consists of real human speech recordings (**bonafide**) and machine-generated or voice-converted speech (**spoof**). The bonafide recordings come from the VCTK corpus — a professionally recorded multi-speaker English speech dataset. The spoof recordings were generated by applying 19 different TTS and voice conversion systems to the same speakers' text transcripts.

### Key Numbers

| Split | Total utterances | Bonafide | Spoof | Attack types |
|---|---|---|---|---|
| Train | 25,380 | 2,580 (10.2%) | 22,800 (89.8%) | A01–A06 |
| Dev | 24,844 | 2,548 (10.3%) | 22,296 (89.7%) | A01–A06 |
| Eval | 71,237 | 7,355 (10.3%) | 63,882 (89.7%) | A07–A19 |
| **Total** | **121,461** | **12,483** | **108,978** | **A01–A19** |

## 2. Data Collection Methodology

### Bonafide Speech

The bonafide speech comes from **VCTK (CSTR Voice Cloning Toolkit)** corpus, which contains recordings from 109 English speakers with various accents. Each speaker read approximately 400 sentences from newspaper text and other sources. Recordings were made in a professional sound studio at the University of Edinburgh.

The key properties of bonafide recordings:
- Professionally recorded in a near-anechoic chamber
- 48kHz original sample rate (downsampled to 16kHz for ASVspoof)
- High signal-to-noise ratio — no significant background noise
- Diverse speaker demographics: different genders, ages, and UK English accents

### Spoof Speech

Each of the 19 TTS/VC systems was used to generate spoofed versions of the same utterances spoken by VCTK speakers. The generation methodology was:

1. Take a target utterance from a bonafide VCTK speaker
2. Feed the corresponding text to the TTS system (for TTS attacks) or feed the source waveform to the VC system (for VC attacks)
3. Optionally adapt the TTS/VC system to the target speaker using enrollment recordings
4. Produce a synthesized waveform

The diversity of systems was deliberately chosen to cover different generations of synthesis technology, from classical statistical systems to modern neural approaches.

## 3. Audio Format

### FLAC (Free Lossless Audio Codec)

All files in ASVspoof 2019 are stored in **FLAC format** (`.flac` extension). FLAC is important to understand for several reasons:

**Lossless compression**: Unlike MP3 or AAC, FLAC preserves every bit of the original PCM audio. This matters enormously for a research dataset — any lossy compression would introduce its own artifacts that might confound the detector. If files were MP3-compressed, the model might learn to detect MP3 artifacts rather than synthesis artifacts.

**Efficient storage**: FLAC typically achieves 40–60% compression of raw PCM audio without any information loss. The full ASVspoof 2019 LA dataset is approximately 27 GB as FLAC, compared to ~45 GB as uncompressed WAV.

**Broad software support**: FLAC is supported by soundfile, torchaudio, and virtually all audio processing libraries. Our `load_waveform` function in `src/data/dataset.py` reads FLAC files directly via soundfile without any intermediate conversion.

### Sample Rate: 16kHz

All files are sampled at **16,000 samples per second (16kHz)**. This choice reflects the standard for speech processing:

- **Telephone quality**: Traditional telephone systems use 8kHz. 16kHz doubles the temporal resolution and captures frequencies up to 8kHz (Nyquist limit).
- **Speech information**: The fundamental frequency of human speech is 80–300Hz. The most important formants (resonant frequencies that carry vowel identity) are at 0–4kHz. Fricatives and sibilants extend to 8kHz. Almost all linguistically relevant speech information is below 8kHz, so 16kHz sampling captures everything useful.
- **Memory efficiency**: 16kHz is 4x smaller than 64kHz "studio quality" audio. For a dataset of 121k utterances, this matters practically.
- **Historical convention**: 16kHz has been the standard for ASV and ASR research since at least the 2000s, making results directly comparable across papers.

Our fixed-length window is 4 seconds × 16,000 samples/sec = **64,000 samples** per utterance. This is the input dimension to RawNet2 and the basis for computing mel-spectrogram frames.

### Mono Audio

All files are single-channel (mono). When `soundfile.read()` returns multi-channel audio (which should not happen for this dataset but can for other sources), `load_waveform` averages channels:

```python
if waveform.shape[0] > 1:
    waveform = waveform.mean(dim=0, keepdim=True)
```

## 4. Protocol File Format

The protocol files are plain text files with one utterance per line. They define which audio files exist, what attack type generated them, and whether they are bonafide or spoof.

### File Locations

```
data/ASVspoof2019_LA_cm_protocols/
├── ASVspoof2019.LA.cm.train.trn.txt   # Training set protocol
├── ASVspoof2019.LA.cm.dev.trl.txt     # Development set protocol
└── ASVspoof2019.LA.cm.eval.trl.txt    # Evaluation set protocol
```

### Format Specification

Each line contains exactly 5 space-separated fields:

```
LA_0031 LA_T_1138215 - A01 spoof
^       ^             ^ ^   ^
|       |             | |   |
|       |             | |   Label: "bonafide" or "spoof"
|       |             | Attack type: "A01"-"A19" or "-" for bonafide
|       |             Always "-" (reserved for future use)
|       Utterance ID — matches the FLAC filename without extension
Speaker ID — identifies which VCTK speaker
```

### Annotated Example

```
LA_0031 LA_T_1138215 - A01 spoof
```

- `LA_0031`: Speaker 31 from the LA partition of VCTK
- `LA_T_1138215`: Utterance ID. The corresponding audio file is `data/ASVspoof2019_LA_train/flac/LA_T_1138215.flac`
- `-`: The third field is always a hyphen in the 2019 dataset (unused)
- `A01`: Generated by attack system A01
- `spoof`: This utterance is spoof (machine-generated)

```
LA_0043 LA_T_9320832 - - bonafide
```

- `LA_0043`: Speaker 43
- `LA_T_9320832`: Utterance ID
- `-`: Unused field
- `-`: No attack type (this is real speech)
- `bonafide`: This utterance is genuine

### Protocol Parser

The parser in `src/data/protocol.py` handles this format:

```python
parts = line.strip().split()
speaker_id   = parts[0]
utterance_id = parts[1]
attack_type  = parts[3] if parts[3] != "-" else None
label        = parts[4]
```

Note that `attack_type` is set to `None` for bonafide utterances (where the field is `-`). This distinction matters for per-attack EER computation in `src/evaluation/eer.py`.

The parser returns a pandas DataFrame with columns:
- `speaker_id`: string identifier
- `utterance_id`: string identifier
- `file_path`: full resolved path to the `.flac` file
- `label`: `"bonafide"` or `"spoof"`
- `attack_type`: `"A01"` through `"A19"` or `None`

## 5. Dataset Splits and Statistics

### Training Set

- **25,380 total utterances**
- **2,580 bonafide** (10.2%) — from 20 speakers
- **22,800 spoof** (89.8%) — 3,800 utterances per attack type × 6 attack types
- Attack types: A01, A02, A03, A04, A05, A06
- Protocol file: `ASVspoof2019.LA.cm.train.trn.txt`
- Audio directory: `ASVspoof2019_LA_train/flac/`

### Development Set

- **24,844 total utterances**
- **2,548 bonafide** (10.3%) — from 20 speakers (different from train)
- **22,296 spoof** (89.7%) — variable counts per attack type
- Attack types: A01, A02, A03, A04, A05, A06 (same as train)
- Protocol file: `ASVspoof2019.LA.cm.dev.trl.txt`
- Audio directory: `ASVspoof2019_LA_dev/flac/`

The dev set is used for:
- Monitoring EER during training (early stopping criterion)
- Model selection (save checkpoint when dev EER improves)
- Hyperparameter tuning

### Evaluation Set

- **71,237 total utterances**
- **7,355 bonafide** (10.3%)
- **63,882 spoof** (89.7%) — variable counts per attack type
- Attack types: A07 through A19 (13 attack types, all unseen during training)
- Protocol file: `ASVspoof2019.LA.cm.eval.trl.txt`
- Audio directory: `ASVspoof2019_LA_eval/flac/`

The eval set is used only for final evaluation. No hyperparameter decisions should be based on eval set results.

## 6. Attack Types

### A01 – A06: Training and Development Attacks (Known)

These six attack types were used to generate the training and development sets. Models trained on ASVspoof 2019 have direct exposure to the artifacts of these systems.

| Attack | Type | System Description |
|---|---|---|
| A01 | TTS | Neural waveform model (neural vocoder with GAN-based post-filtering) |
| A02 | TTS | Waveform concatenation synthesis |
| A03 | TTS | Statistical parametric synthesis (HMM-based with neural vocoder) |
| A04 | TTS | Neural source-filter model |
| A05 | VC | Voice conversion via spectral mapping with neural vocoder |
| A06 | TTS | Neural TTS with Griffin-Lim vocoder |

The exact system specifications were not fully disclosed by the organizers to prevent optimized countermeasures. What is known is that A01–A06 all use vocoders based on frame-by-frame spectral prediction — which leaves characteristic high-frequency artifacts.

### A07 – A19: Evaluation Attacks (Unknown / Unseen)

These 13 attack types appear only in the evaluation set. A correctly generalizing countermeasure should work on these without having seen them during training.

| Attack | EER (LCNN) | EER (RawNet2) | Category |
|---|---|---|---|
| A07 | 0.0000% | 1.2644% | Neural vocoder — WaveNet-family |
| A08 | 0.8158% | 6.9613% | Waveform concatenation |
| A09 | 0.1224% | 1.0582% | Neural source-filter |
| A10 | 0.5846% | 1.2237% | Neural TTS with AR vocoder |
| A11 | 0.3663% | 1.1557% | Transformer TTS |
| A12 | 0.7750% | 1.6859% | WaveNet vocoder |
| A13 | 0.7937% | 2.6252% | Waveform synthesis |
| A14 | 0.5088% | 1.6044% | Statistical parametric |
| A15 | 1.5228% | 1.4652% | Hybrid neural/statistical |
| A16 | 0.0000% | 2.1571% | Waveform concatenation |
| A17 | 36.8457% | 40.3807% | **Neural codec (EnCodec-style)** |
| A18 | 9.7477% | 40.8221% | **Neural codec variant** |
| A19 | 0.0611% | 12.6988% | Traditional synthesis |

### The A17/A18 Problem

A17 and A18 represent a qualitatively different category of attack. Neural codecs are end-to-end learned audio compression systems (similar in principle to EnCodec, SoundStream, or Descript Audio Codec). They encode audio into discrete tokens and decode back to waveforms. When used for TTS, the generated speech has:

- **No high-frequency aliasing**: Neural codecs explicitly model the full spectrum
- **High temporal coherence**: The codec creates smooth transitions that vocoders may not
- **Perceptually matched quality**: They are trained to minimize perceptual error, not just spectral error

Our LCNN achieves 36.8% EER on A17 — barely better than random (50% would be completely random). The Grad-CAM analysis confirms that the model has no focused attention for A17, indicating it has no learned feature that discriminates these attacks.

## 7. Train/Dev/Eval Split Design

### Why A01–A06 for Train/Dev, A07–A19 for Eval

This split is intentional and encodes a specific research question: **can a countermeasure generalize to completely unseen attack families?**

If the eval set used the same attacks as the training set (just different utterances), a model could memorize attack-specific features and achieve artificially low EER. The challenge would be measuring overfitting to specific systems, not generalization ability.

By using entirely different attack types in the eval set, the challenge measures whether the model learned something fundamental about synthetic speech — or just the fingerprints of six specific TTS systems.

### Speaker Disjoint Sets

The speakers in train, dev, and eval are different from each other. This prevents the model from memorizing speaker-specific characteristics. Speaker identity should not help distinguish bonafide from spoof — only synthesis artifacts should.

### The Generalization Gap

This project's LCNN achieves:
- **Dev EER: 0.0000%** (perfect on A01–A06, same families as training)
- **Eval EER: 7.0724%** (good but imperfect on A07–A19)

The dev-to-eval gap (0% to 7.07%) is not a sign of overfitting in the traditional sense — the model never saw A07–A19 in training. It reflects the real-world challenge that features learned on one family of attacks do not perfectly transfer to another family, even when both are "vocoder-based."

## 8. Class Imbalance Analysis

### The 9:1 Spoof-to-Bonafide Ratio

Across all three splits, approximately 89.7–89.8% of utterances are spoof and 10.2–10.3% are bonafide. This severe imbalance has several implications:

**For training:** A naive model can achieve 89.8% accuracy by always predicting spoof. Unweighted cross-entropy loss would allow this degenerate solution. We use weighted cross-entropy to prevent this:

```
weight[bonafide] = total / (2 × count_bonafide) = 25380 / (2 × 2580) = 4.9186 ≈ 4.92
weight[spoof]    = total / (2 × count_spoof)    = 25380 / (2 × 22800) = 0.5566 ≈ 0.56
```

The formula is the standard inverse-frequency weighting: each class's loss contribution is scaled by the inverse of its prevalence. The bonafide class gets ~8.8× more weight per sample than the spoof class, counteracting the 8.8:1 sample ratio.

**For evaluation:** EER is immune to class imbalance by design (see Section 7 of `01_problem_and_motivation.md`). However, per-attack EER computation requires care — each attack subset must contain both bonafide and spoof samples (using all bonafide from the split vs. spoof from that specific attack).

**For the softmax threshold:** The default softmax threshold of 0.5 is not optimal for an imbalanced dataset. EER-based evaluation implicitly finds the optimal threshold — another reason EER is preferred over accuracy.

```

After downloading and extracting, the `data/` directory should have the following structure. The `scripts/check_dataset.py` script validates this layout.

```

├── ASVspoof2019_LA_train/
│   └── flac/
│       ├── LA_T_1000137.flac

    └── flac/

### Naming Conventions

- Train files: `LA_T_xxxxxxx.flac`
- Dev files: `LA_D_xxxxxxx.flac`
- Eval files: `LA_E_xxxxxxx.flac`

The `utterance_id` field in the protocol files matches the filename without the `.flac` extension. The `parse_protocol` function in `src/data/protocol.py` constructs the full path by joining `audio_dir / f"{utterance_id}.flac"`.
